BITRIXFLOW
Complete Sales Operations & Lead Distribution Platform
Master Technical Specification (Part 1)
Version: 1.0 Status: Architecture Lock Document Project Type: External Workflow & Sales Operations Platform for Bitrix24 Client: Premier Choice International Primary CRM: Bitrix24 Primary Industry: Real Estate

1. EXECUTIVE SUMMARY
BitrixFlow is a complete external Sales Operations Platform that extends Bitrix24 CRM.
The purpose of BitrixFlow is not to replace Bitrix24.
Instead:
Bitrix24 remains the primary CRM and user workspace.
BitrixFlow becomes:
Lead Distribution Engine
Workflow Manager
Assignment Controller
SLA Manager
Escalation Engine
Reporting Engine
Audit & Compliance Layer
Marketing Attribution Layer
WhatsApp Notification Hub
The platform is designed to solve operational problems commonly found in high-volume real estate sales environments.
These include:
Unfair lead distribution
Missed follow-ups
Agent inactivity
Lead ownership disputes
Lack of accountability
Poor manager visibility
Weak source attribution
CRM misuse
Inconsistent assignment logic

2. BUSINESS OBJECTIVES
The system must achieve the following objectives.
Objective 1
Ensure every lead is assigned fairly.
Objective 2
Ensure every lead receives timely follow-up.
Objective 3
Ensure managers can monitor agent performance.
Objective 4
Ensure every action is auditable.
Objective 5
Ensure source-to-sale visibility.
Objective 6
Ensure operational scalability.
Objective 7
Ensure all assignment rules are configurable.
No hardcoded logic should exist inside source code.

3. SYSTEM PHILOSOPHY
The platform follows three principles.
Principle 1
CRM Data Lives In Bitrix24
Bitrix24 remains:
Lead Database

Sales Workspace

Principle 2

BitrixFlow controls:

SLA

Principle 3

No hardcoded:

Teams
Sources
Stages
Pipelines

Everything configurable.

5. CORE MODULES

MODULE 2
Lead Distribution Engine
Purpose:
Determine who receives a lead.
Supported Assignment Methods:
Simple Round Robin
A → B → C → A

Active Round Robin
Skip inactive agents.

Load Balanced
Assign to least-loaded agent.

Hybrid Assignment
Default method.
Priority:
Active Agent
Lowest Lead Load
Oldest Assignment Timestamp

Weighted Assignment
Lead distribution based on agent weight.
Example:
Senior Agent = Weight 3
Junior Agent = Weight 1

Source-Based Assignment
Different sources routed to different teams.

7. DEVELOPMENT PRINCIPLES
The system must never contain:
Hardcoded User IDs
Hardcoded Team Names
Hardcoded Stage IDs
Hardcoded Source IDs
Hardcoded Pipelines
All configuration must be stored in database and editable through dashboard.
This ensures long-term maintainability and scalability.
